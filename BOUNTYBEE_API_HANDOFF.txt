How BountyBee should connect
----------------------------

Set these environment variables in the Next.js BountyBee project:

BOUNTYBEE_API_URL=http://127.0.0.1:8081
AUTH_API_URL=http://127.0.0.1:8081
AUTH_SERVICE_KEY=the-same-service-key-used-by-webwallet
JWT_SECRET=next-cookie-secret

For production, replace http://127.0.0.1:8081 with the real backend URL.


Required headers
----------------

Server-to-server calls must include:

X-Service-Key: shared-service-key
Content-Type: application/json
Accept: application/json

Protected user routes must also include:

Authorization: Bearer external-session-token


Auth flow
---------

1. Signup:

POST /api/v1/auth/signup

Body:

{
  "email": "user@example.com",
  "password": "password123",
  "address": "1BSVAddress...",
  "encrypted_key": "encrypted-wallet-key"
}

Response includes:

{
  "success": true,
  "user_id": 1,
  "email": "user@example.com",
  "address": "1BSVAddress...",
  "token": "external-session-token",
  "token_ttl_seconds": 604800
}

2. Login:

POST /api/v1/auth/login

Body:

{
  "email": "user@example.com",
  "password": "password123"
}

Response includes the same token shape.

3. Verify session:

POST /api/v1/auth/verify

Body:

{
  "token": "external-session-token"
}

4. Load current user:

GET /api/v1/users/me
Authorization: Bearer external-session-token


Important response shapes
-------------------------

Marketplace task list:

GET /api/v1/marketplace/tasks

Returns:

{
  "tasks": [],
  "stats": {
    "totalTasks": 0,
    "featuredTasks": 0,
    "totalReward": 0,
    "matchingTasks": 0
  },
  "categories": [],
  "nextCursor": null
}

Wallet summary:

GET /api/v1/wallet

Returns flat wallet fields plus nested wallet:

{
  "address": "1BSVAddress...",
  "paymail": "alice@bountybee.io",
  "availableBalance": 0,
  "pendingBalance": 0,
  "reservedBalance": 0,
  "recentTransactions": [],
  "wallet": {}
}

BSV price:

GET /api/v1/market/bsv-price

Returns both old and new compatible fields:

{
  "usd": 50,
  "estimated": true,
  "priceUsd": 50,
  "cached": true,
  "updatedAt": "2026-06-06T00:00:00.000Z"
}


BSV signing rule
----------------

Do not send plaintext BSV private keys to normal backend routes.

For real payout/withdrawal:

1. Client calls:
   POST /api/v1/wallet/withdraw/quote

2. Client fetches encrypted key:
   POST /api/v1/auth/wallet-key

3. Browser decrypts/signs locally with user password.

4. Client sends signed transaction:
   POST /api/v1/wallet/withdraw/broadcast

The backend stores accounting, task, escrow, transaction, and notification records. It does not safely sign real BSV transactions unless a dedicated signing service is added.

Deployment note
---------------

After changing server.py, restart the Flask backend running on port 8081.

On Windows, find the process:

Get-NetTCPConnection -LocalPort 8081 -State Listen

Then restart webwallet with the same AUTH_SERVICE_KEY that BountyBee uses.
